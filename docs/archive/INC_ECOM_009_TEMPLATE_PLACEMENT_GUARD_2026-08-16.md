# INC-ECOM-009｜模板空位落位与层级门禁修复

状态：`PRODUCTION_PUBLISHED_AUTO_PASS / USER_RECHECK`

## 现象与根因

新发布的三条服装自动上新模板把最外层 `template-group` 写成了自己的父节点，线上图数据因此不存在顶层节点。画布仍然执行空位搜索，但 `offsetTemplate` 只平移无 `parentId` 的顶层节点，所以模板保持原始固定坐标并覆盖已有节点。

生产只读审计确认：仅模板 `0901/0902/0903` 存在 `group.parentId === group.id`，其他公共模板和用户模板未发现同类结构。

## 修复范围

1. 修正服装自动上新模板编译器：Group 永远作为顶层节点，只有子节点绑定 `parentId`。
2. 加强共享 `validTemplateGraph`：拒绝错误版本、重复节点/边、孤儿父节点、自引用、Group 嵌套、零顶层节点及缺失边端点。
3. 加强发布器内部图校验，确保即使绕过管理 API 也不能写入同类错误。
4. 事务修复生产三条模板数据，只移除外层 Group 的错误 `parentId`，不改变节点、连线、提示词、模型或封面。
5. 回归验证空画布、密集画布和同模板连续导入不重叠；发布前后不调用 Provider，不创建生成任务。

## 验收标准

- 三条新模板各有且仅有一个顶层 Group，所有非 Group 节点仍指向该 Group。
- 空位计算后的位移真实作用于模板 Group；连续导入两次包围盒不重叠。
- 公共模板与用户模板保存入口均拒绝自引用 Group。
- 生产数据库 `schema39 / quick_check=ok / FK=0 / active generation=0`，服务 `active/enabled`，版本/live/ready 正常。
- 生产修复前完成可恢复备份，写入失败时事务回滚。

## 实施结果

1. 模板编译器已修正：外层 `template-group` 不再写入 `parentId`，三份工作流分别为 `9/15`、`10/18`、`15/30` 个节点/连线，均严格为一个顶层 Group。
2. 发布器已增加发布前层级校验和仅针对旧自引用缺陷的 `--repair-parent-hierarchy` 事务修复模式；合成数据库验证了首次发布、重复发布、修复 dry-run、修复 apply 和修复幂等二次执行。
3. 服务端共享 `validTemplateGraph` 已拒绝重复节点、Group 自引用/嵌套、孤儿父节点、零顶层节点、重复/缺失边端点和自环，管理端与公共模板写入口共用该门禁。
4. 定向回归 `m70 + m77 = 19/19 PASS`；正式安全全量 `118/118 specs、966/966 tests PASS`，失败/跳过/重试/阻断均为 0。
