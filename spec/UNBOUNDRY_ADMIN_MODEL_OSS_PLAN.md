# Unboundry 管理员模型中心、账号权限与 OSS 实施规划

状态：`AUTHORITATIVE PLAN / PHASE A-F ACCEPTED / PHASE G VIDEO + API-001～006 ACCEPTED / PHASE H INPUT PARTIAL / PHASE I RELAY-001～012 ACCEPTED / MUREKA AUDIO REAL GENERATION+DEPLOY DEFERRED`
更新时间：2026-08-04

## 1. 已确认的产品决定

- 系统只有两种账号：`管理员`和`普通用户`。
- 管理员配置生成平台、模型、节点可用范围、默认参数和后台保护规则。
- 普通用户只能在节点创作栏选择管理员已经发布的模型。
- 普通用户看不到 Provider、接口地址、密钥、OSS 配置和后台成本。
- 用户侧不显示额度或积分；服务器仍保留并发、频率、费用和紧急停止保护。
- OSS 使用项目自有账号和私有 Bucket，由服务器统一读写。
- 团队项目、邀请、成员协作和公开注册继续暂停。
- OpenRouter真实Image链路已经通过；同一任务、权限、安全与OSS结构已复用到火山方舟Seedance Video，Audio继续等待单独指令。
- 管理员日常操作固定为“平台连接→添加模型→发布给节点”，不暴露厂商原始JSON或任务协议。
- 第一版平台连接支持OpenRouter、火山方舟和OpenAI兼容中转站；特殊非标准接口以后按适配器单独增加。
- 节点入参按统一平台中立schema管理；未来模型可配置输入类型、数量、角色、组合和必填条件，不要求改写四个节点。
- 用户明确要求Text目标接受Text、Image、Video、Audio四类上游；这是本项目增强，不冒充Unboundry当前实测事实。

## 2. 权限边界

### 管理员

- 创建、禁用和重置普通账号。
- 查看、创建、编辑、启用和停用模型。
- 决定每种节点可以使用哪些模型及默认模型。
- 查看 Provider 和 OSS 是否配置成功，但默认不回显完整密钥。
- 设置全局/用户并发、频率、费用上限和紧急停止。
- 查看不含密钥的管理操作和任务错误记录。

### 普通用户

- 访问自己的画布、任务、历史和素材。
- 在节点中查看并选择已启用、适配当前节点的模型。
- 提交、取消或重试自己有权限的真实任务。
- 不得通过直接调用接口访问管理设置或其他用户数据。

### 暂停

- 自助注册。
- 团队空间、邀请、成员管理和多人实时协作。
- 普通用户自带 Provider Key 或 OSS。

## 3. 最终结构

```text
管理员后台
  ├─ 模型目录与节点绑定
  ├─ Provider 配置状态
  ├─ OSS 配置状态
  ├─ 并发/频率/费用保护
  └─ 管理审计

普通用户画布
  └─ 只读取“当前节点可用模型”
       → 服务端鉴权
       → 模型配置快照
       → SQLite 持久任务
       → Provider 任务执行器
       → 私有 OSS 原子落盘
       → 节点与账号历史共同发布
```

浏览器永远不直接持有 Provider Key 或 OSS AccessKey。

## 4. 实施阶段

### 阶段 A：数据保护与迁移底座

目标：在加入账号字段前确保现有数据不丢失。

实施：

1. 为 SQLite 增加版本化迁移记录。
2. 迁移前备份现有 SQLite、WAL 和媒体目录。
3. 创建首个管理员后，把现有画布、历史、媒体和任务归属到该管理员。
4. 现有本地素材保持可读；不强制一次性搬迁 OSS。
5. 开发 fixture 使用隔离测试账号，不改变已人工通过的验收入口。

验收：

- 迁移前后节点、连线、视野、标题、历史和媒体数量一致。
- 旧素材仍可播放和下载。
- 备份可以在新目录恢复。

### 阶段 B：账号、登录和两级权限

目标：恢复必要的 `AUTH-001`，但不扩大到团队系统。

实施：

1. `users`：管理员/普通用户、启用/禁用状态和安全密码摘要。
2. `sessions`：服务器会话、过期、注销和失效。
3. 首次初始化只允许创建一个管理员。
4. 关闭公开注册；普通账号由管理员创建。
5. 登录、项目、画布、媒体、历史和任务统一经过服务器鉴权。
6. 管理接口统一要求管理员角色，前端隐藏只是辅助。

验收：

- 未登录不能访问项目、媒体和任务。
- 普通用户不能访问管理接口或其他用户数据。
- 禁用账号的已有会话立即失效。
- 管理员可以正常管理普通账号。
- 直接构造 URL 或请求也不能绕过权限。

### 阶段 C：管理员模型中心

目标：实现“管理员配置，普通用户只选择”的 Unboundry 式体验。

数据结构：

- `provider_profiles`：Provider 名称、安全配置引用、超时、并发和启停。
- `model_profiles`：用户显示名称、能力类型、真实模型编号、默认参数、排序和启停。
- `node_model_bindings`：Text/Image/Video/Audio 与可用模型的绑定。
- `admin_audit_events`：谁在何时修改了什么，不保存完整密钥。

密钥策略：

- 密钥由管理员在专属网页的密码输入框提交，不保存到浏览器或普通 SQLite 字段。
- 服务端使用AES-256-GCM和服务器主密钥写入`data/secrets`专用加密文件。
- 管理后台只显示“已加密保存”和末尾少量掩码；修改时留空可保留原密钥。

用户接口只返回：

- 模型 ID、显示名称、能力类型、允许参数、默认值和可用状态。

不返回：

- Provider Key、OSS Key、接口地址、内部模型路由和后台成本。

任务提交时保存模型配置版本快照。管理员之后修改模型，不改变已经提交的任务。

验收：

- 普通用户只看到当前节点允许的模型。
- 停用模型立即从新任务中消失，但历史任务仍可解释。
- 普通用户直接请求管理接口返回无权限。
- 生产包、网络响应、日志和错误中没有密钥。

### 阶段 D：自有私有 OSS

目标：普通用户不配置 OSS，项目服务器统一管理素材。

实施：

1. 使用私有 Bucket 和最小权限 RAM 身份。
2. OSS 凭证只存在服务器受限配置。
3. 数据库只保存自有媒体 ID、对象键、类型、大小、归属和校验信息。
4. 对象键使用随机 ID，不写邮箱、原文件路径或其他隐私信息。
5. 参考素材交给 Provider 时生成短时签名地址。
6. 生成结果先完整上传并校验，再发布到节点和历史。
7. 临时对象设置自动过期；正式结果不跟随节点删除。
8. 旧本地媒体与新 OSS 媒体并行读取，稳定后再决定是否迁移旧文件。

验收：

- 匿名访问 Bucket 和永久直链失败。
- 用户只能读取自己的媒体。
- 签名地址过期后失效。
- 上传失败不产生数据库残留，数据库失败不发布半成品。
- 图片、视频和音频支持完整读取、Range 和下载。

### 阶段 E：后台保护，不恢复用户额度 UI

目标：取消额度显示，但防止费用失控。

实施：

- 全局生成总开关。
- 每个用户并发上限。
- 每分钟请求上限。
- 图片、视频、音频分别设置任务上限。
- 管理员每日/月度费用警戒与停止线。
- Provider 连续失败后暂停新任务。
- 任务成本和结果数量写入管理员审计，不展示成用户积分。

验收：

- 超限请求在调用 Provider 前被拒绝。
- 紧急停止不会接受新任务。
- 已运行任务按管理员选择安全取消或等待完成。
- 无法确定成本时默认阻止高风险请求，而不是无限放行。
