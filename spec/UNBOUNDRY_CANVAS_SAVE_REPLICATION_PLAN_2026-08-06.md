## 1. 背景与证据

### 1.1 Unboundry 真实保存机制（前端代码取证）

`useTapflowPersist`（vendor-pkg-canvas 3XsW7E77）：

- 节点/连线变化转换为增量操作 `create/update/delete`，按节点合并去重（create+update → create，delete 覆盖）；
- 防抖 **500ms**，队列达 **50 条**立即批量提交；
- 提交带 `created_by_role` + `session_id`（每会话/标签页一个），服务端按会话顺序应用 → “最后修改者胜”；
- 失败重试 **3 次**，退避 `2.5s × 2^n`，上限 30s，失败操作重新入队不丢；
- `beforeunload` 时队列未清空弹出“有未保存更改”；
- 位置在拖动结束（`dragging=false`）才记录，尺寸在 resize 结束才记录；
- **没有“画布必须已保存才能生成”的门禁**，生成与保存并行。

### 1.2 当前项目机制

- 整张画布文档 `canvas_documents`（nodes/edges JSON）全量 PUT；
- 防抖 1000ms，带 `revision / graph_revision / saveSessionId / saveSequence`；
- 冲突 409 → “另一画布已保存更新”并提示刷新（DATA-005 已实现最后修改者胜）；
- **生成门禁**：`canvasRevision === undefined` 时禁止生成/整组执行（已实测导致“第一个节点成功后后续层被跳过”）；
- 多标签用 BroadcastChannel 通知保存，但整文档覆盖，不同节点并发编辑会互相覆盖。

## 2. 第一步（强化版，确认后实施，等用户指令）

目标：根治“保存窗口误拦生成”，对齐 Unboundry 的保存节奏与冲突体验，**不改变服务端存储结构**。

### Phase 0 保险前置（必做）

- git 基线：开始前工作区干净并记录当前 commit；
- 全量备份：数据库 + 媒体目录，执行 `data:backup` 并校验备份可用；
- 新增配置开关 `canvasPersistenceMode: "legacy" | "v2"`（默认 `legacy`），旧路径完整保留；
- 把回滚手册写进本文档（见 Phase 6）。

### Phase 1 基础设施（不改变行为）

- 新增 `waitForCanvasClean(timeout)`：封装现有“排空保存队列 + revision 确认 + 最新一次渲染后的版本读取”，供节点与整组执行共用；
- 保存失败状态显性化：失败时状态栏显示“保存失败，请检查网络”，不做无声失败；
- 新增默认关闭的诊断日志开关。

### Phase 2 生成与保存解绑（v2 子开关，默认关）

- 节点登记入口的 `run()` 先 `await waitForCanvasClean()`；该函数必须做到：
  “排空保存队列 → 版本号确认 → 等一帧渲染 → 取最新 ref 再调用生成”，防止旧闭包复用；
  8 秒超时，失败给出友好提示，不静默跳过；
- 整组执行层间复用同一入口，避免遗漏；
- 服务端 409：自动刷新 revision 并**只自动重试一次**；再 409 则停止并一次性提示
  “内容已在其他页面更新”，不循环、不弹“请刷新”；
- 服务端 `canvasRevision` 校验仍保留作为最终兜底（不能因为前端解绑就失去服务端防线）。

### Phase 3 保存节奏（v2 子开关，默认关）

- 防抖 1000ms → 500ms（可配置），仍按文档指纹去重（无变化不发请求）；
- 多个 pending 保存合并为一次（新文档覆盖旧 pending），避免请求堆积；
- 拖动结束 / resize 结束才入队（回归确认）。

### Phase 4 冲突与未保存提醒（v2 子开关，默认关）

- 409 不再弹 reload：采用最后修改者胜，并一次性 toast“内容已在其他页面更新，已采用最新版”；
- 本页仍有未提交本地修改时，先提交本地再重读；文档明确“不同节点并发编辑可能被后保存者覆盖”的边界；
- `beforeunload`：队列非空时弹原生未保存提醒。

### Phase 5 测试与验收

- 新增专项：
  - 整组执行“第一节点成功后第二层继续执行”（真实沙盒复现原 bug）；
  - 输入文字后立即手动 Generate（画布 dirty 时）可提交；
  - 409 自动重试不弹窗；
  - `beforeunload` 提醒；
- 自动化测试覆盖**等待契约**：用打桩方式让假节点成功并把画布变脏，断言 runner 会等待并继续；
  端到端真实生成链路由用户真实验收一次；
- 回归：m3 持久化 / revision 冲突 / 重启恢复、m22 整组执行、m14 额度、模板契约、
  DATA-005 最后修改者胜、“另一画布已更新”不再弹窗；
- 用户真实验收。

### Phase 6 上线与回滚

- 先开“生成解绑”子开关，用户验收；再开“500ms + 冲突优化”子开关；
- 开关为环境变量 `UNBOUNDRY_PERSISTENCE_MODE`，切换需重启服务（几秒），已写入回滚手册；
- 任一异常：开关切回 `legacy`（代码保留双路径，行为立即还原）；
- 需要彻底回档时：先停服务，再 git revert + 恢复备份（数据库 + 媒体），避免覆盖运行中的新数据；
- 每次开关状态与验收结果记录到 TASKS.md。

### 第一步明确不做

- 服务端增量接口、节点级跨标签合并、本地队列持久化（全部在待办）；
- 不改变 `canvas_documents` 结构与历史数据。

## 5. 预审计（2026-08-06 强化版风险与应对）

| # | 风险 | 应对 |
|---|---|---|
| 1 | `waitForCanvasClean` 若只等队列不等渲染，旧闭包会复用，原 bug 复发 | 实现=排空队列→版本确认→等一帧渲染→取最新 ref；专项测试模拟“首层成功后画布变脏”断言第二层等待并继续 |
| 2 | 409 自动重试可能覆盖另一标签页刚保存的内容 | 只自动重试一次，再 409 即停止并提示；文档明确“谁最后提交谁生效”边界，真合并留待办 |
| 3 | 开关放环境变量需重启、放数据库需加管理面 | 第一步用环境变量（默认 legacy），三个子开关默认全关；回滚手册写明重启步骤 |
| 4 | 保存失败静默，500ms 高频后更易感知 | Phase 1 显性化失败状态；生成提交被等待函数拦截并给友好提示 |
| 5 | 自动化测试无法烧钱做真实生成链路 | 自动化覆盖等待契约（打桩假成功+画布变脏）；端到端由用户真实验收 |
| 6 | 防抖降低后请求变多、旧多标签提示回潮 | 文档指纹去重+pending 合并；回归清单含 DATA-005 与“不再弹更新提示” |

### 边界（第一步明确接受）

- 不同节点在多个标签页并发编辑时，后提交方可能覆盖先提交方（最后修改者胜）；
- 保存请求已带 `keepalive`，`beforeunload` 仅在“队列非空且未在发送”时提醒；
- 中文输入法合成结束才提交，500ms 防抖不会保存半截拼音。
