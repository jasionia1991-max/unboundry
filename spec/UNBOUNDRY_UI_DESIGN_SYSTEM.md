# Unboundry 项目级 UI Design System

状态：`AUTHORITATIVE FOR UI / CURRENT BASELINE / DOCUMENTATION ONLY`  
基础视觉基线日期：2026-08-03；媒体尺寸与选择层级增量更新：2026-09-06
适用范围：Canvas、Text/Image/Video/Audio 节点、引用卡、固定外壳、Provider、模型中心及其他 Admin 页面。

## 0. 文档定位

本文件是本项目后续视觉设计和 UI 实现的统一规范来源。它总结当前已经形成、已经自动约束或已经由用户人工验收的视觉语言，不创造一套新的风格，也不授权重构已有 PASS 界面。

本文件只管理视觉与界面表达，不改变功能、范围和验收状态：

- 功能、范围、PASS/PARTIAL/PAUSED/BLOCK 以 `TASKS.md` 和 `UNBOUNDRY_ACCEPTANCE_MATRIX.md` 为准。
- Unboundry 事实以 `UNBOUNDRY_REFERENCE_EVIDENCE_CATALOG.md`、状态 fixture 和实页勘测为准。
- 节点入参的产品规则以生成架构、两轮上游勘测和复制计划为准。
- 当前代码、CSS 和自动检查用来证明“现在实际如何显示”，不能单独把人工待验收项目改成 PASS。
- `INPUT-001～INPUT-007`继续保持 PARTIAL；本文件不改变验收状态。下一批计数由`TASKS.md`与验收矩阵维护，2026-08-04用户明确要求提前同步后当前为6/10。

文中使用三个标记：

| 标记 | 含义 |
|---|---|
| `硬契约` | 已有明确验收、fixture 或自动检查，不得在普通开发中改动 |
| `当前模式` | 当前代码已经稳定形成的视觉模式，新功能应优先沿用 |
| `待统一` | 已发现差异或风险，只登记，不在本次文档任务中修改 |

## 1. 设计原则

### 1.1 macOS 原生、克制、高信息密度

- 使用 macOS 原生系统字体和紧凑控件。
- 主要依赖灰度、轻边框、间距和字重建立层级。
- 不使用巨大后台控件、浏览器默认蓝色选中块或鲜艳的大面积状态色。
- 同一界面最多两种字号；不靠放大标题制造层级。

### 1.2 内容优先

- Canvas 中素材、节点和连线是主角，工具栏和菜单应悬浮、紧凑、按需出现。
- Admin 中配置内容优先，页面采用高密度卡片和分级控件，不把每个操作都做成 46px 大按钮。
- 空态、加载、失败、不兼容和数量超限必须在当前操作区域内说明，不能只留下暗淡按钮。

### 1.3 真实状态优先

- 未接入、禁用、失败、权限不足必须如实显示。
- 不用视觉假成功替代真实能力。
- 模型不兼容时保留用户的 edge 和引用卡并说明原因，不静默删除内容。

### 1.4 保留已验收几何

- 已人工通过的节点尺寸、工具栏、菜单、固定锚点、响应式页面和交互状态不得因“统一样式”被推翻。
- 新的共享组件只能承接共性；存在真实产品差异时保留组件级变体。
- 修改任何已验收界面前，必须先列出受影响的 fixture、测试和人工验收项。

## 2. 视觉层级与色彩

### 2.1 基础色

| 角色 | 当前基线 | 使用范围 |
|---|---:|---|
| Canvas 背景 | `#000000` | 真实画布、空画布、节点工作区 |
| Admin 页面底色 | `#080808` | 后台页面底层 |
| Admin 点阵 | 24px 间距、低透明白点 | 后台页面背景，不覆盖内容 |
| 节点与 Creator 主表面 | `#1f1f1f` | 节点卡、四类生成输入框 |
| Admin 主卡 | `rgba(30,30,31,.97)` | 模型、Provider、存储、安全等主卡 |
| 深层输入表面 | `#141415` / `#171718` | 文本输入、列表卡、Provider 卡 |
| 二级表面 | `#252525` / `#292929` / `#2b2b2b` | 引用卡、参数区、紧凑行 |
| 浮层表面 | `#242426`～`#303032` | 菜单、选择器、悬浮控件 |

`硬契约`：Canvas 必须保持纯黑背景。Admin 的点阵与轻微灰色光晕只属于后台页面，不得带入节点内部。

### 2.2 文本色

| 角色 | 当前基线 |
|---|---:|
| 主文字 | `#f5f5f5` / `#f2f2f2` |
| 正文 | `#cccccc`～`#dedede` |
| 辅助文字 | `#a9a9a9` / `#9a9a9f` |
| 弱文字 | `#7a7a7a`～`#8f8f93` |
| 禁用文字 | 在原颜色基础上降低透明度，不换成浏览器默认蓝灰 |

同一语义允许 Canvas 与 Admin 因底色不同有轻微灰度差，但新页面应优先使用上表层级，不再新增近似但无语义的新灰色。

### 2.3 边框与分隔

- 主边框：`1px solid rgba(255,255,255,.10～.13)`。
- 节点默认边框：`1px solid #333333`。
- 节点选中：`2px solid #7a7a7a`，不得恢复蓝色描边。
- 轻分隔线：`rgba(255,255,255,.08～.14)`。
- 引用卡默认边框：`#3b3b3b`。

### 2.4 语义状态色

Provider/Admin 已形成最稳定的状态色，作为新界面的推荐基线：

| 状态 | 文字 | 背景 |
|---|---:|---:|
| 成功/有效 | `#bfe6d0` | `rgba(74,169,116,.16)` |
| 失败/无效 | `#ff9ea6` | `rgba(201,72,85,.16)` |
| 警告/未知/权限不足 | `#e3bd90` | `rgba(184,128,65,.16)` |
| 未检查/普通 | 灰色 | 低透明灰底 |

Canvas 入参状态当前使用：

- `invalid / missing / empty / blocked`边框：`#a96443`。
- `uploading`边框：`#7d68d8`。
- 阻塞原因文字：`#e2a07d`。
- `ready`使用默认灰色边框，不额外刷绿色大块。

`待统一`：历史页面仍有多组近似错误色和警告色。新功能采用上表，旧页面只在单独回归与人工验收后逐步迁移。

### 2.5 阴影与模糊

- 节点 Creator 常用：`0 16px 44px rgba(0,0,0,.38)`。
- 浮层常用 12～18px 的纵向阴影和约 32～48px 的模糊范围。
- 固定工具栏可使用 `backdrop-filter: blur(16px)`。
- Admin 主卡片通常不使用重阴影，依靠底色和细边框区分。
- 禁止用蓝色发光表示选中或键盘焦点。

## 3. Typography

### 3.1 字体栈

`硬契约`：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display",
"Helvetica Neue", Arial, sans-serif
```

- 表单、按钮、菜单、节点正文和后台页面全部继承该字体栈。
- 禁止重新引入 Inter、Roboto、Segoe UI 作为显式字体。

### 3.2 仅允许两档字号

| 角色 | 字号 | 说明 |
|---|---:|---|
| 主字号 | `14px` | 正文、按钮、输入、主标题、节点正文 |
| 辅助字号 | `12px` | 节点标题、说明、状态、标签、tooltip |

- 标题仍为 14px，通过 `font-weight: 600/700`、颜色和间距建立层级。
- 不新增 16px、18px 或更大的后台标题。
- 行高按内容使用 1.3～1.65；Creator 正文常用 22px 行高。

对应自动契约：`tests/m18-typography.spec.ts`会检查 Canvas、菜单、四类 Creator 和全部 Admin 页面。

## 4. 间距与圆角

当前代码尚未把间距、圆角完全抽成变量；以下是已经形成的角色规则，不表示代码已经有完整 token 系统。

### 4.1 常用间距

| 间距 | 推荐角色 |
|---:|---|
| `2px` | 工具栏紧邻图标、选择器菜单项间隔 |
| `4px` | 小控件 padding、菜单外层 padding、紧凑 gap |
| `6px` | 引用卡组、微型内容组 |
| `8px` | Creator 内部、常规字段、按钮组 |
| `10px` | 紧凑卡片和行内分组 |
| `12px` | 二级卡片、参数面板 |
| `20px` | Admin 双栏和主区块间距 |
| `24px` | Admin 主卡片内边距 |
| `28px` | Admin 页面内边距 |

### 4.2 圆角层级

| 圆角 | 推荐角色 |
|---:|---|
| `4px` | 紧凑 checkbox |
| `6～9px` | 预览、小按钮、菜单项、引用卡 |
| `10～13px` | 输入框、选择器、二级卡片 |
| `14px` | Provider/模型列表卡 |
| `16px` | Canvas 节点、Creator、上下文菜单 |
| `20px` | Admin 主卡片 |
| `24px` | 登录卡、少数已验收大弹层 |
| `999px / 50%` | 胶囊工具栏、状态标签、圆形图标按钮 |

不得为了“统一”把所有圆角强行改成同一数值；圆角代表组件层级。

## 5. 基础组件

### 5.1 Button

| 类型 | 当前尺寸 | 当前外观 |
|---|---|---|
| 表单主按钮 | 高 `46px`，圆角 `12px` | 浅底深字，字重 700 |
| 页面/导航按钮 | 最小高 `38px`，圆角 `10px` | 深灰底、浅色细边框 |
| Admin 紧凑操作 | 高 `34～36px`，圆角 `9～11px` | 深灰底、浅文字 |
| Provider 行内操作 | 最小高 `30px`，圆角 `8px` | 高密度次按钮 |
| Canvas 工具栏图标 | `40×40px` | 透明底，hover 出现灰底 |
| Creator 普通按钮 | 高 `32px`，圆角 `8px` | 透明或轻灰底 |
| Creator 生成按钮 | `32×32px`，圆形 | 可用时浅底深图标 |

状态规则：

- hover 使用 `rgba(255,255,255,.06～.12)`灰色叠层。
- 不可用：`cursor: not-allowed`并降低透明度。
- 保存中：可使用 `cursor: wait`，不得与永久不可用混为同一语义。
- Creator 生成按钮禁用基线为 `opacity: .35`。
- 按钮文字不应折行；窄布局应换行组件或改变布局，而不是挤压文字。

危险按钮：当前项目尚无经过统一验收的危险按钮组件。删除、立即停止等操作不得被文档虚构为已有通用样式；新增危险操作必须单独设计、确认语义和回归范围。现有页面保持原状。

### 5.2 Input / Textarea

| 类型 | 尺寸 | 视觉 |
|---|---|---|
| 普通 Admin 输入 | 高 `46px`、圆角 `12px` | `#141415`、13% 白色边框 |
| 紧凑参数输入 | 高约 `34px`、圆角 `9～11px` | 深灰底、紧凑 padding |
| 目录凭证输入 | 最小高 `36px`、圆角 `8px` | `#181819` |
| Creator textarea | 14px、透明底 | 由外层 Creator 提供边界 |

Focus：

- 文本输入边框提高到约 38% 白色，并使用 3px 低透明灰色外环。
- 参数控件可用 1px 浅灰 outline，`outline-offset: 2px`。
- Canvas textarea placeholder 使用 `#777～#7a7a7a`。
- `待统一`：Admin placeholder 尚未显式冻结颜色，新页面不得凭空扩散新的 placeholder 色。

### 5.3 Checkbox

`当前模式`：新的 Admin checkbox 统一使用紧凑自绘样式。

- 尺寸：`16×16px`。
- 圆角：`4px`。
- 默认背景：`#141415`。
- 默认边框：`rgba(255,255,255,.34)`。
- 选中背景：`#ececee`，深色勾。
- focus-visible：3px 浅灰外环。
- disabled：`opacity: .45`，`cursor: not-allowed`。

必须使用专用 checkbox 组件或 class。禁止让裸 `input[type="checkbox"]`继承 `.admin-card input`的 `100% × 46px`文本输入框规则。

当前正确示例：Provider 模型目录和“创建后立即发布”。  
`待统一`：模型参数区仍存在 13px/15px 原生 checkbox，只有在专项回归与人工验收后才能迁移。

叠加在封面/亮色内容上的选择勾选框（如工作空间项目卡片）**不得使用黑色实心底**：未选中使用白色边框 + 浅白半透明底，选中使用浅底白框 + 深灰勾，保证在明暗封面上都清晰且不出现黑色方块。

### 5.4 Switch

项目目前没有通用 Admin Switch。

- Agent 局部开关为 `36×20px`、16px thumb，是该局部组件，不是全局规范。
- 存储路由和生成安全使用语义按钮，不得自动改造成滑动开关。
- 新增通用 Switch 前必须单独定稿并补自动检查；不得借此恢复暂停的真实 Agent 能力。

### 5.5 Select / Dropdown

- Canvas 和 Admin 使用自绘灰色菜单，不使用浏览器蓝色选中背景。
- 普通 Admin select：46px 高、12px 圆角。
- 紧凑参数 select：34px 高、11px 圆角。
- 菜单背景约 `#242426～#28282b`，圆角 12px，内边距 5～6px。
- 选项最小高 32～38px，hover/focus 用灰色底；选中使用更亮灰底和浅色勾/文字。
- 菜单接近视口底部时应向上展开，不允许被卡片或视口裁切。
- 面板内的少量固定选项（≤4 项且无长列表）优先使用内联选项组（`inline-option-group`，30px 高、8px 圆角、`#303032` 底、选中 `#464649` 底 + 高亮边框），不使用弹出下拉；弹出下拉仅保留给动态或长列表选择（模型目录、调用协议、筛选条件等）。内联选项组与创作器参数面板按钮共用同一套视觉规格，避免同一面板内出现“悬浮浮层”观感。

### 5.6 Card

- Admin 主卡：24px 内边距、20px 圆角、12% 白色边框、`rgba(30,30,31,.97)`背景。
- 列表卡：13～16px 内边距、12～14px 圆角、`#171718`或近似深灰背景。
- 二级配置卡：9～13px 内边距、9～13px 圆角。
- Canvas 节点：16px 圆角；Creator 也是 16px，但与节点主体分层。
- 卡片标题用 14px，辅助说明用 12px；不新增大号后台标题。

### 5.7 Status Tag

- 使用胶囊形 `999px`圆角。
- 文字 12px，padding 通常 5～10px。
- 颜色只表达有效、失败、未知/权限、普通四类语义。
- 不用状态标签代替操作按钮，也不把“已保存”误写成“Key 有效”。

### 5.8 Menu / Popover / Modal

- Canvas 上下文菜单常用 16px 圆角、4px 外层 padding。
- 普通菜单项约 32px 或 44px 高；来源感知菜单项为 52px。
- Tooltip 使用 12px 字号、约 8px 圆角，不遮挡主要操作。
- Escape 关闭当前最上层界面，外点关闭适用的浮层，焦点返回触发按钮。
- 已冻结的搜索、快捷键、素材库、历史、角色库等面板继续以各自 fixture 的精确尺寸为准，不能被一个“通用 Modal 尺寸”覆盖。
- `硬契约`：节点「全屏」是画布级遮罩层，禁止走浏览器/系统 Fullscreen API。图片与文字共用同一套半透明黑底、圆角面板、标题栏和关闭方式（Escape / 点暗处 / ×）；浏览器地址栏保持可见，四周可隐约透出画布。文字层中间为只读正文，字多时在面板内滚动，动作按钮为「复制」而不是「下载」。视频详情里单独标注的「浏览器全屏」不在此列。
- `待统一`：Admin 当前仍有原生 `window.confirm`，尚无项目级 Admin Modal；本文件不虚构一个已验收弹窗组件。

### 5.9 Provider 错误提示

Text/Image/Video/Audio 的本地生成状态提示共用 `ProviderErrorNotice` 及既有横幅样式；输入引用问题仍由引用卡解释。当前验收与部署状态由[当前状态](UNBOUNDRY_CURRENT_STATE.md)拥有，以下约束与对应代码、测试相核对；第4版新增部分单独标注，生产结论以当前状态和发布回执为准。[本轮证据](VIDEO_BALANCE_SINGLE_NODE_RECOVERY_PLAN_2026-09-07.md)。

- 默认只显示一行中文摘要（12px，沿用失败态 `#f1b0b0`/暗红半透明底），英文/长平台原文不再直接铺满横幅。
- 平台原文存在时，摘要旁显示紧凑「查看原文」按钮（22px 高、6px 圆角、浅灰细边框）；展开后原文以 12px `code` 块展示，可复制。
- 已经是中文的本地错误不重复显示原文，也不出现「查看原文」。
- 交互不引入第三种字号、蓝色焦点或大号按钮；按钮与现有错误横幅按钮同规格。
- 先按真实状态区分：输入缺失/无效保留引用卡阻塞提示；自动重连/找回/保存显示中性过程状态；确认失败才使用失败横幅。四类节点一致执行，Audio不能把恢复过程一律作为红色`alert`。同一任务、同一原因只保留一处主要提示，恢复成功后移除旧提示，不同时叠加引用错误、预览横幅和全局弹窗。
- 平台文案的翻译/关键词匹配只用于展示，不能据此确定任务失败、未扣费或开放重试；未知结果不得被通用摘要误写成“平台已拒绝”。「查看原文」和复制只能使用已整理的安全诊断文本，不接入完整响应、密钥、请求正文或临时签名URL；`providerErrorParts`经 `sanitizeProviderDiagnostic` 清理网址、凭据字段及控制字符，诊断区限长；这只保护展示和复制，不构成服务端证据或计费判断。
- 接入验收须覆盖四类节点的长中文/英文、多引用与多个不同提示、窄节点、画布缩放、原文展开/收起/复制及键盘焦点。沿用现有原文区滚动限高，不把文本撑出节点、不挤掉生成/取消/检查按钮；提示及详情不能遮挡工具菜单，保留6.5「浏览全部」浮层规则。文字完整可访问，不以截断隐藏原因冒充布局通过。不得为显示提示改变画布节点/组的持久尺寸、位置或层级。

| 服务端事实 | 普通用户看到什么 | 可执行动作 |
| --- | --- | --- |
| 原任务查询有实际活动，或存在正在执行的原结果保存任务 | 中性提示“正在找回上次结果，你可以继续编辑其他内容” | 无必点重试；可查看处理进度 |
| 原查询退避中，服务端确已安排下一次检查且未超预算 | “已安排自动核对，你可以继续编辑其他内容” | 无必点重试；未安排下一次检查不能使用这条文案 |
| 维护待办已持久登记，尚无人认领 | “自动恢复暂未完成，已登记待处理” | 查看进度；不显示“工作人员正在处理” |
| 管理员已认领 / 明确登记等待平台证据 | 分别显示“维护人员已接手” / “正在等待模型平台确认”，附最后更新的时间 | 无任务号/日志/账单填写要求；无假百分比和倒计时承诺 |
| 自动恢复已停且待办登记失败，或读取服务不可用 | “暂时无法更新处理状态，原任务已保留” | 保留待同步状态，恢复连接后自动补读；不假称已入队或反复全局弹错 |
| 原结果保存并按原绑定投影成功 | 结果回到节点，移除旧错误，任务入口记录“原结果已找回” | 查看结果；无额外生成 |
| 有结果但原节点已变更/删除，无法安全应用 | “原结果已找回，当前节点有变化，可查看原结果” | 在原owner任务详情查看；仅经现有合法应用命令才写回，不覆盖新内容 |
| 精确失败结算完成且新生成准入通过 | “上次生成已结束，可重新生成此节点” | 一个主要动作“仅重新生成此节点”，提前说明新一轮可能收费；需要改输入/充值则显示该具体前置条件 |
| 仍缺平台证据，无法安全继续 | “尚未取得平台确认，当前任务仍未解决”，保留最后跟进事实 | 保持原请求保护；不重复摆放已知无效的检查按钮，不显示“已解决” |

以上继续使用同一`ProviderErrorNotice`、字号、色彩和动作尺寸；等待维护是中性状态，不能仅凭文案关键词认定后台仍在自动恢复。只保留一个主提示和一个主要动作。用户主动开始新一轮但尚未提交时，当前输入/保存等阻断原因优先显示，不能被旧任务“可继续”提示盖住，也不能被随后完成的排队编辑或其他节点保存清除；下次明确提交或任务/结果更新时清理当前提交提示。旧任务状态仍保留在历史中，不改变其证据或准入结论。节点提示与任务历史来自同一服务端摘要；进展未读标记按服务端版本保存，打开旧消息不能标掉刚到达的新进展。状态变化通过礼貌的可访问提示呈现，轮询不抢焦点、不重复播报。顶部“已保存”仍只代表画布保存。维护入口复用现有Admin页面样式与真实管理员鉴权，操作区文字区分“查看/认领/核对原请求”，不提供“强制解锁/确认已退款”按钮。站内通知不等于已发送站外消息。

并行状态的主提示优先级：已投影原结果→结果已找回待保存/绑定变化→当前实际原请求恢复活动→已安排且未超预算的下一次自动核对→持久维护阶段→无法确认处理状态。维护与自动恢复同时存在时，维护阶段只在同一进度详情显示，不再叠加第二条横幅；“已接手”与“等待平台”必须分别有认领和跟进记录。活动依据有效工作器/租约/请求状态，下一次核对依据持久检查点及工作器可用性，单纯case排队或时间窗口尚未结束都不能冒充自动工作。服务端无法确认活动时使用保守提示，不凭客户端动画保活。

保存冲突修复合同补充（实施、上线与用户验收状态见当前状态）：保存与原请求找回继续复用中性过程提示和既有`ProviderErrorNotice`；不把后台扫描冲突写成模型失败。原结果找回后清除旧错误；原节点变更时说明“可查看原结果”。已失败组可继续时，在任务入口自动加载后继预览，只给一个“继续未完成节点”主要动作，并说明已成功结果会保留、后续生成可能收费。预览短暂读取失败要自动补读，不能使入口无声永久消失。重复提交与超时以服务端持久关系为准，不能要求用户提供任务号、日志或手动核查账单。既有节点白框、工具菜单、端口、比例和模板布局规则继续适用。

## 6. Canvas 专用规范

### 6.1 画布与坐标

- 全屏纯黑背景，页面不出现浏览器原生滚动条。
- 点阵基础间距 20px、偏移 `-11px`、基础半径 0.5；缩放时点阵同步变强或变弱。
- zoom 范围 `0.15～2`。
- screen UI 不随 Canvas zoom 缩放；节点、Group、端口、edge 使用 world 坐标。
- 固定锚点和响应式误差上限为 1 CSS px。
- `硬契约`：搜索定位只消费一次，不得在后续缩放中反复拉回viewport。
- `硬契约`：光标在节点、input/textarea/contenteditable或打开的Creator上时，画布缩放仍必须生效；缩放事件应按画面帧合并，不得使Creator闪烁或丢失焦点。
- `硬契约`：viewport保存与节点/edge内容保存分层；纯缩放不得显示“画布正在保存”、不得阻塞生成。

### 6.2 节点外观

- 节点主体背景：`#1f1f1f`。
- 默认边框：`1px solid #333333`。
- 圆角：16px。
- 选中：`2px solid #7a7a7a`，无蓝色阴影。
- 节点标题位于主体上方，12px、低透明浅灰。
- Text 正文与占位为 14px。
- Image、Video、Audio 素材使用 `contain`，不得无依据裁切。

### 6.3 默认尺寸与媒体比例

| 节点 | 默认尺寸 |
|---|---:|
| Text | `250×250` |
| Image | `250×250` |
| Video | `444×250` |
| Audio | `444×250` |
| Playlist | `960×104` |
| Storyboard/Table 历史只读样本 | `1200×1000` |

- 横向媒体以高 250px 为基准，16:9 为 `444×250`。
- 竖向媒体以宽 250px 为基准，9:16 为 `250×444`。
- 新图片/视频、空模板媒体和历史素材新节点使用auto；只在可信素材接管/生成结果投影时按比例适配。手动resize记录manual，可通过“按素材比例适配”显式恢复auto并撤销。
- `mediaSizingMode`分auto/manual；旧节点没有此字段时保留既有大小，不批量迁移。刷新/播放/metadata加载不得写尺寸。
- 模板内位置与持久zIndex保留；竖素材使节点变高可能重叠，由用户手动整理，不自动重排。选组或组内节点时整个组临时置于未选组前方；失选恢复，不保存临时层级。这里的“选中”要求节点selected=true；应用模板仅设置primaryId并不自动选中，不能把此规则描述成“新插入模板自动置前”。
- 视频预览使用受容器约束的完整contain，不裁切下半部；该规则与全屏完整显示一致。v0.7.14已有本地及线上USER_PASS，证据见`V0_7_14_PRODUCTION_RECEIPT_2026-09-06.json`。
- “无 resize control”的正确含义是未选中时不显示可见控件；选中后仍保留八个透明拉伸区。
- Text/Image/Video/Audio 的主体卡片、外层选中框和拉伸区域必须使用同一持久尺寸；默认大小和手动拉伸下限不能变成卡片加载时的 CSS 最小尺寸。历史或导入的小节点仍完整包在选中框内，不能通过刷新/选中自动放大节点来掩盖问题。

### 6.4 端口与 edge

- 节点左右可见连接加号约 24×24px，实际透明命中区约 80×80px。
- 未选中且未 hover 时端口隐藏；hover 或选中后显示。
- 普通 edge：`#7a7a7a / 1.5px`。
- 选中 edge：`#f5f5f5 / 2px`。
- 交互命中宽约 20px；连线删除剪刀是独立悬浮动作。
- 禁止组合不得创建正式 edge，应保留来源感知菜单，让用户创建适配节点。
- edge 是引用关系唯一事实来源；引用卡不得另存一份平行关系。
- 来源菜单覆盖 Text/Image/Video/Audio。Text 提供文本、图片、视频、音频四项；其余沿用 Image 5 项、Video 4 项、Audio 2 项的布局。可用动作遵守现有节点输入矩阵：Text→文本/图片/视频/音频、Image→文本/图片/视频、Video→文本、Audio→视频。其余选项真实禁用、灰显并显示原因，不以无响应按钮代表未接入能力。
- 点击可用项仅原子新增一个适配节点和一条引用 edge，支持保存、刷新和撤销；不自动开始生成。Text 来源由节点类型在内存推导，不扩展持久化 sourceKind 或 schema。
- 打开、取消菜单及缩放/平移不得重新加载整张画布、清空草稿或中止现有保存。菜单留在可见区域，临时线随来源节点、分组和视口变化保持连接；取消后清理临时线。
- 来源菜单打开后聚焦首个可用项；Escape 或点击画布空白取消后，焦点回到来源节点。直接点击其他节点或可聚焦控件时保留新目标的交互，不把焦点抢回旧来源。

### 6.5 工具栏

- 通用浮动工具栏高 48px，深灰半透明背景，胶囊形，blur 16px。
- 常规图标按钮 40×40px，hover 显示灰底；tooltip 为 12px。
- Text 格式栏、Image/Video 工具栏的已验收尺寸继续按各自 fixture，不强行统一总宽度。
- 工具不可用时必须真实 disabled，不显示假动作成功。
- 图片顶部「浏览全部」展开菜单必须显示在下方Creator之上，所有可用项目均可点击；仅临时提升展开浮层，不改变节点/组的持久层级、几何或工具栏尺寸。

#### 6.5.1 多选公共工具栏

- `硬契约`：选中两个或以上节点时，全屏只能显示一条 screen-space 公共工具栏。
- 多选成员的单节点Toolbar、Creator、标题输入、播放器、临时菜单和resize chrome必须全部收起；回到单选时立即恢复原节点界面。
- 画布非编辑区的拉框和`Cmd+A`不得产生浏览器原生文字选区；input、textarea、select和contenteditable区域仍允许正常选字。
- 公共“打组”只在全部已选项均为可打组的顶层普通节点时启用，继续使用既有Group的20px包围盒、父子坐标、撤销和持久化契约；不得静默只组合部分已选节点，不得给子节点强加`extent: parent`。

`待裁决`：`TASKS.md`保留 Audio 工具栏 `215×48`的人工验收记录，而当前自动检查断言 `183×48`。本文件不选择任何一方覆盖另一方；后续涉及 Audio 工具栏时必须先做证据裁决，不能顺手修改。

### 6.6 Creator

- 外层使用 16px 圆角、1px 低透明边框、`#1f1f1f`背景和轻阴影。
- 内部正文 14px；辅助、模型状态和参数摘要 12px。
- 底部控制区高 40px，普通按钮高 32px。
- 生成按钮只有在输入、模型、Provider 和安全门禁都满足时亮起。
- 禁用时必须在 Creator 内显示最主要的阻塞原因；不常态显示无意义的“暂无参数”。
- Text、Image、Video、Audio 可有不同宽度和字段，不为表面一致强行合并成一个巨型通用节点。

## 7. 上游引用卡与输入状态

本节描述当前 P0/P1 实现候选的 UI 基线，不改变 `INPUT-001～INPUT-007 = PARTIAL`。

### 7.1 统一卡片

- Text、Image、Video、Audio 共用同一引用卡组件。
- 卡片宽 200px，最小高 44px，padding 4px，gap 7px，圆角 8px。
- 预览区约 `38×36px`、圆角 6px、背景 `#161616`。
- 图片显示缩略图；视频显示封面/预览；音频显示小波形；文字显示类型标记和摘要。
- 卡片必须同时显示：来源标题、类型、角色、顺序、状态、阻塞原因和删除入口。
- 删除按钮 `22×22px`；删除卡等价于删除对应 edge，撤销同时恢复。
- 卡片组横向滚动，不挤压 Creator 主输入区。

### 7.2 状态

| 状态 | UI 含义 |
|---|---|
| `empty` | 已连接，但来源没有可用内容 |
| `uploading` | 来源正在上传或生成，暂不能提交 |
| `ready` | 来源内容与必要元数据已就绪 |
| `invalid` | 内容损坏、类型错误或当前规则不接受 |
| `missing` | edge 仍在，但来源节点/素材已经找不到 |

- `missing`和模型不兼容都不得静默删 edge。
- 模型切换后默认保留引用卡，并在卡内与卡组下方说明阻塞原因。
- 角色变化、数量超限、组合冲突和 Prompt 缺失应显示具体原因。

### 7.3 角色和顺序

- 角色来自当前目标节点、模型和模式，不由卡片组件写死。
- 可见角色包括生成指令、上下文、普通参考、首帧、尾帧、主体等。
- 顺序显示为稳定序号；删除中间卡后，新引用不得复用已有顺序造成重复。
- 角色可切换时使用紧凑灰色选择控件；当前模型不允许时禁用并说明原因。

### 7.4 最终 Prompt

- Image 的上游 Text 可作为母版；本节点 Prompt 为空时使用母版。
- 两者都有时显示“母版 + 本节点补充”后的最终 Prompt。
- 最终 Prompt 区为深灰二级卡，圆角约 7px，标签 12px，正文 14px。
- UI 只显示最终文本；任务快照还必须包含来源节点、素材 ID、类型、角色和顺序。
- 不显示或保存短期 OSS 签名地址。

## 8. Admin 专用规范

### 8.1 页面骨架

- 页面 padding：28px。
- 通用页头和布局最大宽：960px。
- Provider 页面最大宽：1100px。
- 主区块间距：20px。
- 模型中心默认双栏；视口宽 928px 以下改为单栏。
- Provider、存储和生成安全在 760px 以下改为单栏。
- 不同页面断点服务各自内容密度，不强行合并成一个数字。

### 8.2 模型中心

- 左侧负责新增与参数配置，右侧是模型卡片列表。
- 模型列表卡使用 `#171718`、14px 圆角、约 14px 内边距。
- 参数编辑使用 34px 高的紧凑输入和自绘灰色下拉。
- 最末下拉接近视口底部时向上展开。
- 模型参数组合展开后必须留在卡片内部，不产生页面横向溢出。
- 普通用户只看已发布模型；内部编号、Provider 和密钥不进入节点 UI。

### 8.3 Provider

- 平台选择卡最小高 82px、圆角 14px。
- 已保存连接卡最小高 108px、圆角 14px。
- 模型目录作为卡内二级卡：13px 内边距、12px 圆角、12px 间距。
- 发现模型列表最大高 330px，单行最小高 50px；长列表使用卡内滚动。
- Key 状态与模型目录状态分开显示，不能把“目录可读”误写成“生成权限完整”。
- 模型目录 checkbox 必须使用 16px 紧凑自绘样式。
- 对用户使用“添加到模型中心”，不使用难懂的“导入草稿”。添加后默认停用、非默认，管理员检查并启用后普通用户才可见；该动作不得自动发起生成。

### 8.4 存储中心

- 顶部状态横幅、两张主卡、配置列表保持分层。
- 统计格三列，每格最小高 80px、圆角 12px。
- 配置卡最小高 116px、圆角 13px。
- 密钥只显示掩码和状态，不回显完整值。
- 存储连接测试、正式启用和新素材路由必须在文案与状态上分开。

### 8.5 生成安全

- 顶部状态横幅、两个高优先级控制卡和规则卡保持清晰分层。
- 高优先级控制卡最小高 180px。
- 主要语义按钮高 42px、圆角 12px。
- 运行中任务策略使用整行选择卡，最小高 68px、圆角 12px。
- 生成安全控制是语义按钮，不自动改成 Switch。

### 8.6 Table 与 Admin Modal

- 当前模型、Provider、存储和安全页采用卡片列表，没有已验收的共享 Admin Table。
- 当前部分危险确认仍使用浏览器原生确认框，没有已验收的共享 Admin Modal。
- 新功能不得为了补齐“组件大全”而虚构 Table 或 Modal；需要时先设计、自动检查、再人工验收。

## 9. 交互、焦点与无障碍

- 所有图标按钮必须有可读名称或 tooltip。
- Escape、外点关闭和焦点返回遵循已验收的浮层规则。
- Shell 键盘焦点使用 `0 0 0 2px rgba(245,245,245,.72)`灰色焦点环。
- 输入和自绘选择器使用灰色边框/外环，不使用浏览器默认蓝色。
- hover 与 focus 必须可区分；不能只依赖鼠标悬停。
- disabled 控件保留可读文字，使用透明度和光标表达，不完全隐藏原因。
- `待统一`：Admin 普通按钮尚未全部拥有共享 focus-visible 规则。
- `待统一`：当前没有 `prefers-reduced-motion`统一规则；生成动效和过渡只能在独立回归后补齐降动效方案。

## 10. 响应式与密度

已验收的 Canvas 视口：

- `1135×917@2x`
- `1280×720@2x`
- `1440×900@1x`
- `1512×982@2x`
- `1920×1080@1x`

规则：

- 1280px 是当前最小可靠 Canvas 支持宽度；低于该值不宣称 1:1 完整支持。
- Canvas 固定锚点误差不超过 1 CSS px。
- Admin 可在更窄宽度下改单栏，但不得产生水平滚动或控件越出卡片。
- 响应式优先换列、换行和调整菜单展开方向，不缩小到第三种字号。

- 使用灰度层级、细边框和紧凑间距。
- checkbox 使用专用 16px 组件/class。
- 在禁用按钮附近显示真实阻塞原因。

- 模型不兼容时保留 edge 并说明原因。
- 节点首次按素材比例适配，之后保留用户人工尺寸。
- 新 Admin 页面优先复用 46/38/34/30px 四级密度。
- 修改已验收视觉前先列出 fixture、自动测试和人工复验范围。

### Don't

- 不使用浏览器默认蓝色 select、checkbox 或 focus ring。
- 不让裸 checkbox 继承 46px 文本输入框样式。
- 不在同一界面引入第三种字号。
- 不把所有后台按钮都做成大号主按钮。
- 不把所有圆角、按钮高度或页面断点强行合并为一个值。
- 不用灰色禁用按钮代替具体错误说明。
- 不因切换模型静默删引用或 edge。
- 不把短期 OSS 签名地址写入卡片、节点或任务快照。
- 不为写规范而重构已 PASS 的 Canvas、节点或 Admin 页面。
- 不恢复已取消的 Comment、社区、TapTV、竞技场、额度/积分和链接分享。

## 14. 变更门禁

任何后续 UI 改动都应按以下顺序：

1. 先确认功能范围与当前验收状态，排除取消、暂停或阻塞功能。
2. 标明使用本文件的哪一条规则，以及是否碰到已知差异。
3. 列出受影响组件、fixture、自动测试和用户已通过页面。
4. 保留已有数据、节点几何、edge、媒体引用和 Provider 安全边界。
5. 先完成零 Provider 自动检查；UI 检查不得创建真实图片、视频或音频任务。
6. 通过构建和定向回归后，再打开真实本地页面给用户验收。
7. 自动检查不等于人工 PASS；未经用户确认不得修改验收矩阵状态。
8. 验收文档仍按累计 10 次成功人工验收集中同步，除非用户明确要求提前更新。
