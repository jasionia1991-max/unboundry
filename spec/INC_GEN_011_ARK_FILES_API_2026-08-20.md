# INC-GEN-011 方舟文字模型大图原图直传（Files API）

状态：`IMPLEMENTED_RELEASED`（2026-08-20 已随 v0.6.24 上线，待用户线上复验；隔离安全全量 1006/1006 全绿、真实方舟验证已通过）
日期：2026-08-20
权威快照：`spec/UNBOUNDRY_CURRENT_STATE.md`

## 用户要的结果

火山方舟文字模型引用参考图时，超过 10MB 的 PNG 不再被拦下、也不再压缩，而是原图直传，任务照常跑完。以后这类「平台限制」问题，项目文档里要有清晰的修改口子和排查路径，用户自己也能照着改。

## 现状与根因（已逐条核实）

1. 普通用户上传图片入口上限 20MB（上传、服务端读取、通用媒体规则、生成预检共四层都是 20MB）。
2. 火山方舟文字任务单独限制图片 10MB、只收 PNG，超过就红字拦截。
3. 执行链路先取媒体（本地图转 Base64 / 云端图给签名链接），再进配置锁发请求；Base64 本身有约 10.4MB 的字符上限，所以 10MB 以上的本地图走不出去。
4. 方舟 Files API 平台能力是单文件 ≤512MB，但**我们系统当前入口最多只能到 20MB**，因此本期真实范围是 `10MB < PNG ≤ 20MB`；20MB 以上的资产接入是单独一期，不做。

## 实现范围（收窄版，第一版只做这些）

- 只改原生火山方舟文字路径（`volcengine-ark` driver 的文字任务）。
- 只处理 `image/png`，大小 `> 10MB` 且 `<= 20MB` 的参考图。
- 本地图和云端（OSS）图统一走二进制 multipart 上传（方舟 Files API 的 URL 入参只支持火山 TOS 地址，本项目云存储不是 TOS，因此不做 URL 拉取；OSS 图由服务端签名下载字节后上传）。
- 新增功能开关 `UNBOUNDRY_ARK_FILES_API`，**默认 `0`（关闭）**；关闭时旧路径 100% 不变。验收后显式设为 `1` 才生效。
- 不动其他平台、其他模型、OpenRouter、通用媒体、视频发送。
- 不设版本号、不打标签、不发布；本项只是方案落地前的契约文档。

## 核心设计（实现时必须遵守的契约）

### 1. 只读一致快照（锁语义）

新增「只读 Provider 配置快照」接口，语义与现有正式租约相同，但**只取快照不发起任何平台请求**：

1. 短暂持配置锁，读加密配置文件 + 数据库密钥与版本；
2. 校验两份存储版本一致，返回 `profileId / baseUrl / apiKey / credentialRevision / configurationVersion`；
3. 立即释放锁；
4. 之后的上传、轮询、删除全部在锁外完成；
5. 上传完成后再走现有正式租约，并在锁内用 `requireTaskProviderSnapshot` 校验版本；版本已变化则不发请求、先清理已上传文件。

说明：配置文件写入是「临时文件 + 原子改名」，不会读到半截文件；锁的必要性在于加密配置文件和数据库密钥是两份存储，必须保证读到的是同一版本的完整快照，而不是新配置拼旧密钥。

### 2. 拦截位置

新路径必须在 `providerMediaUrlForOwner`（转 Base64 / 生成签名链接）**之前**接管 10–20MB 的 PNG，避免大图先被转 Base64 触发旧限制。现有 10MB 预检对新路径放行，但只放行 PNG 且只放行到 20MB。

### 3. 请求体契约

- `ArkTextInput` 新增 `fileId?: string`，与 `url` 互斥（二选一，同时出现视为格式错误）。
- `fileId` 只能由服务端构造，用户不可直接提交。
- 请求中图片内容为 `{ type: "input_image", file_id: "file-…" }`，**不再出现大图 Base64**。
- 普通小图继续走现有 `url` 路径，一行不改。

### 4. 文件生命周期

- **不做跨任务缓存**（无 LRU）：每个任务独立上传、独立删除；同一张图被多个节点引用就各自上传一次，换取正确性。
- 上传成功但推理前被取消 / 版本变化 / 任务失败：一律在清理阶段删除文件。
- 进程崩溃残留的文件**不做恢复逻辑**，靠方舟官方过期时间兜底（默认 7 天）。
- 删除失败不影响已经成功的推理结果，只记日志，仍靠过期兜底。

### 5. 取消与清理信号

- 上传、轮询必须响应任务取消（接入现有文字任务 AbortController）。
- 删除文件时**不得复用已经 abort 的信号**，改用独立的短时清理信号，否则取消后删除请求会立刻被中止、留下孤儿文件。

### 6. 限流（不全局串行）

- 按 Provider profile（优创连接）各自限流：同时最多 2 个上传；不同账号/连接互不影响。
- 队列满时有界等待（建议 30 秒，具体值实现评审时定），超时返回明确错误；**绝不无限重试**。
- 二进制上传进内存受同一信号量保护，避免并发吃爆内存。

### 7. 超时（必须明确并测试）

- 上传总超时：60 秒。
- 文件从 `processing` 到 `active` 的轮询总时限：120 秒（轮询间隔 1 秒）。
- 删除超时：10 秒。
- 队列有界等待：30 秒，超时返回明确错误，绝不无限重试。

删除超时最短，且永不阻塞任务收尾。

### 8. 上传与读取策略（第一版全二进制）

- 本地图和 OSS 图都下载/读取字节后 multipart 上传，单文件上限 20MB（当前资产上限），无 URL 回退分支。
- OSS 图使用 600 秒签名 URL（不扩公共 helper）由服务端下载，下载后校验大小、PNG 头、SHA-256。
- 本地图读取沿用现有校验逻辑（大小、格式头、SHA-256 一致才放行），不另起一套。
- 鉴权失败、配额满、格式错误等明确错误**直接失败**，不重试、不回退。

### 9. 计费与 attempt 边界

- 上传、轮询、删除全部发生在 `recordProviderAttempt` 之前；上传失败不产生计费记录、不产生 attempt、不判红字为已付费。
- 只有正式推理请求发出时才写 attempt（沿用现有边界）。
- 上传失败的任务收口沿用现有失败分类（明确错误红字、瞬时错误有界重试/中性提示），不进入无限重试。
- 费用表述：**文件存储以官方规则为准（20GB 免费额度），模型推理按实际规则计费**；不写「不额外收费」的绝对承诺。

### 9. 计费与 attempt 边界

- 上传、轮询、删除全部发生在 `recordProviderAttempt` 之前；上传失败不产生计费记录、不产生 attempt、不判红字为已付费。
- 只有正式推理请求发出时才写 attempt（沿用现有边界）。
- 费用表述：**文件存储以官方规则为准（20GB 免费额度），模型推理按实际规则计费**；不写「不额外收费」的绝对承诺。

### 10. 凭据生命周期

- 上传用到的 API Key 只存在本次内存快照里，不落库、不写日志。
- 旧快照保留到清理结束（删完文件才丢弃）。
- API Key 轮换后，用旧 key 删除文件可能失败：记录日志，靠过期兜底，不误判任务。

## 明确不做

- 不支持 20MB 以上的产品入口（普通用户根本传不进来）；512MB 大资产链路单独一期设计。
- 不改 OSS 签名 helper 的 600 秒上限。
- 不做跨任务 file_id 缓存 / 引用计数复用。
- 不改数据库结构（schema 仍 39）、不改生产数据、不碰真实媒体/备份。
- 不真去方舟出图；任何真实调用都必须用户单独点头。

## 风险 / 回归 / 耦合 / 应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 开关关闭时旧路径回归 | 现有 10MB 内图片全受影响 | 开关默认 0，测试必须覆盖「关闭时旧路径行为完全不变」 |
| 上传/轮询持锁 | 重演线上锁死 | 只读快照后立即释放，锁内严禁任何网络；专项测试确认锁已释放 |
| 取消后残留文件 | 浪费平台存储 | 独立清理信号 + 官方过期兜底；测试覆盖取消清理 |
| 并发二进制上传吃内存 | 服务卡顿 | per-profile 信号量 2 + 有界排队；单文件 ≤20MB |
| 版本变化时误发请求 | 用错配置扣费 | 正式租约内二次校验，变了不发请求并删文件 |
| 上传失败被误判已付费 | 用户看到红字/计费错乱 | 上传在 attempt 边界之前；测试断言无 attempt |
| 删除失败误判任务失败 | 已成功结果被标红 | 删除独立于任务收尾，只记日志 |
| 进程崩溃残留 file | 平台存储缓慢增长 | 不做恢复，官方 7 天过期；文档写明 |

## 测试清单（实现时必须全绿）

1. 10MB、10MB+1、20MB、20MB+1 四个边界。
2. 开关关闭时旧路径行为完全不变。
3. 请求中出现 `file_id`，不出现大图 Base64。
4. 上传、轮询、删除的取消与超时。
5. 上传期间配置版本变化：不发请求、清理文件。
6. 两个并发任务产生不同 file id，互不提前删除。
7. 删除失败不误判推理失败。
8. 上传失败不产生 Provider attempt / 计费记录。
9. Files 上传、轮询期间配置锁未被持有。
10. per-profile 信号量排队：第 3 个上传有界等待或明确报错，不无限重试。
11. URL 拉取失败回退二进制成功；鉴权/配额/格式错误不回退、直接失败。
12. 上传途中取消任务：文件仍被独立清理信号删除。
13. API Key 轮换后删除失败：任务收尾不受影响，仅日志。

## 以后自己怎么改 / 查（维护口子）

- 开关：环境变量 `UNBOUNDRY_ARK_FILES_API`（默认 0）。
- 大小上限：找 `INC-GEN-011` 相关常量（实现时集中放在新文件 `server/arkFileUploader.ts`，不散落）。
- 日志关键字：`ark-files-upload` / `ark-files-poll` / `ark-files-delete`。
- 官方文档：方舟 File API（`https://www.volcengine.com/docs/82379/1795150`），文件单张 ≤512MB、账号 20GB 免费存储、默认存 7 天可设 1–30 天、图片支持 png/jpg/gif/webp。
