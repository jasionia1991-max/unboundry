## 4. 具体设计

### 4.1 一个编辑窗口只对应一个编辑会话

将当前独立的 creating/editing/draft/局部错误等编辑数据收拢为 AdminTemplatesPage 内的局部会话状态。一个会话拥有：唯一递增 sessionId、mode(create/edit)、targetId（仅 edit）、draft、graphDirty、图读取状态与请求编号。页面级在途保存状态独立于窗口。

每次打开新建、打开编辑都生成新 sessionId，重新打开同一个模板也不能沿用旧编号。关闭、取消、外点、Escape 和卸载都使旧会话失效，取消旧 GET。AbortController 只用于释放资源；正确性必须由 sessionId/requestId/来源模板 ID 共同检查，不能假定 abort 一定阻止回调。

图加载的 success、catch 和 finally 均带请求身份。真正写入 React 状态时再次检查当前会话及请求，不能只在发请求前检查。迟到成功不能回填图，迟到失败不能给新窗口报错，迟到 finally 不能清掉新请求的 loading。不要把这套状态提到全站 store，也不顺带拆分整个 App。

### 4.2 手动编辑优先于后台读取

打开编辑时先显示标题等信息和“正在读取模板内容”。元数据与 JSON 仍可输入；用户修改 JSON 的同步处理函数先废弃在途图读取，再写入其输入并设置 graphDirty=true。因此用户主动粘贴/修改后，迟到读取永远不能覆盖它。

未主动改 JSON 时，只有当前读取成功才填入图，graphDirty 仍为 false。编辑模式 graphDirty=false 时，即使初始图仍在读取，也允许只保存元数据，PATCH 必须省略 graph；开始保存时废弃这次图读取，不能再回填正在保存的窗口。手动输入后读取已废弃，可按正常校验保存。只有新建的来源图 pending 时暂不可保存，手动接管或选空后按实际草稿校验。读取失败显示当前窗口错误，并允许重试、手动输入或仅修改元数据。编辑空白 JSON 保持“不提交 graph，保留原图”的既有语义，并显示清楚提示；新建空白 JSON 则拒绝保存。

图不存在、响应里找不到精确 ID、缺失合法 graph 均视为读取失败；不得返回空字符串假装成功。只做当前客户端所需的身份与基本响应形状检查，正式图结构/发布能力校验仍由服务器负责。

### 4.3 “基于现有模板”使用相同隔离规则

图请求编号在 A→B、A→空选项、关闭和手动改 JSON 时都递增，即使新选择为空也要废弃旧请求。回填必须符合最新选择和会话；标题只可在仍为空时采用来源标题，不能覆盖用户正在输入的标题。

每次开始选择新来源时，回退快照必须取当时屏幕上实际显示的 graphJson 原文、graphDirty 和已提交的来源 ID，而不是仅记住“上一次来源读取成功的图”；标题等元数据不随图回退。手动修改图后清除来源 ID，选择框显示“不基于现有模板”，其手工内容成为新的稳定草稿。新的来源选择处于 pending 状态，保存禁用。成功时将新来源 ID 与新图一起提交到草稿。失败时恢复该次请求开始前的精确图/来源/dirty 快照，并说明“来源模板读取失败，保留原内容”。连续 A/B/C 选择复用当前显示的稳定草稿，不能把前一 pending 选择当成已成功来源；只有最后请求允许执行回退。

选择“不基于现有模板”保留当前已显示的稳定图，转为独立手工内容；用户在 pending 期间手动修改 JSON 时，废弃读取并清除 pending 来源，当前手工内容归用户所有，后续返回不再回填。

### 4.4 保存时固定目标和内容

保存函数同步读取并校验当前会话，解析 JSON，构造不可变提交快照（sessionId、targetId、标题、完整序列化 payload）；同一次保存的 URL 和 payload 只能从该快照构造，不在 await 后重新拼接当前 draft。

编辑模式下，只有用户主动修改了非空 JSON 才在 PATCH 中发送 graph；初始自动读取不标记 graphDirty，只改标题时不发送 graph。若同时改图和元数据，仍用同一个 PATCH 原子保存。新建必须提交有效的 graph。

设置页面级同步 ref 保存门禁，再更新可见 saving 状态。不能只依赖下一次 render 后的 disabled，防止快速双击提交两次。一个页面实例同一时刻只有一个在途编辑保存。提交前废弃当前图读取，并冻结正在提交的会话全部可变字段（含标题、JSON、状态、分类、封面及来源选择），保存按钮显示“保存中”；字段修改处理函数也拒绝该会话的在途修改，不能只靠样式。关闭/取消/Escape/外点仍可用，提示“关闭窗口后仍会继续保存”；关闭不取消已经发出的 POST/PATCH，也不宣称服务器已撤销。

保存 A 期间可以关闭并查看/编辑 B；B 的字段不冻结，但保存按钮显示“等待上一项保存”且禁用，不能显示成 B 已在保存。旧保存的成功/失败只能结束自己的在途门禁；仅当对应会话仍存在时才能关闭弹窗或更新 modalError。旧 A 的响应不能关掉 B、改 B 草稿或把 A 的错误贴到 B。页面级结果提示必须使用快照中的模板名；列表刷新不能回填当前草稿。卸载后不更新已卸载 UI。

同模板写入期间，A 的编辑、发布/下架/恢复/归档操作与“把 A 选为来源”入口都暂停，并说明 A 正在保存。相应 handler 同步检查在途 targetId；不允许绕过按钮禁用发 GET 或其他写请求，也不自动排队这些操作。B 的读取继续可用。已有 busyId 的同模板状态操作尚未结束时，编辑保存也应等待，复用现有行级 busy 状态，不建立全站锁。

收到成功响应后，先校验响应的 template 身份并把这条已确认记录写入管理列表，再解锁 A；服务端现有 POST/PATCH 响应就是 `{ template: ... }`（adminTemplates.ts:461-464、490-492），无需新接口。列表 load 也带页面级请求序号：保存开始/确认时废弃旧列表请求，较早列表不得在成功后覆盖这条新记录。解锁后再次编辑 A 或选择 A 为来源必须发新的 no-store 图读取，不能重用保存前在途请求/旧缓存；保存失败保留当前会话草稿并解锁，不把旧读取当作最新结果。

不自动重试 POST/PATCH，也不承诺跨页面重新打开或丢响应后的“恰好一次”语义；本项只保证当前页面在途重复点击被挡住。保存明确失败且窗口仍在时保留草稿供用户处理。

### 4.5 不采纳的扩大方案

- 不单靠“关闭时清空”“比较模板 ID”或 abort：同模板重新打开、同窗口连续换来源、手动输入和迟到错误都会漏掉。
- 不增加 sourceTemplateId 作为安全证明：合法手工复制本就允许跨模板使用图，客户端提供的来源声明也不能让服务器鉴别真实图来源；会扩大接口却不能替代会话隔离。
- 不将一次编辑拆为标题 PATCH 和图 PATCH 两次请求；保留一次事务内的整体保存。
- 不新建单项 GET、不增加数据库版本字段、不重写所有管理页。当前列表未找到图时失败即可，完整分页留在原审计问题 UI-04。

## 5. 可执行验收矩阵

下表是冻结验收要求；实际执行状态以第9节为准。以可控 Promise/路由响应顺序驱动，不用碰运气的 sleep。A/B/C 使用系统临时数据中的不同 UUID、有效 graph 和明显不同的节点文字。

| ID | 场景 | 必须断言 |
|---|---|---|
| TPL-S01 | 编辑 A，关闭后编辑 B；B 先返回 A 后返回 | B 的标题/图/错误不变；实际 PATCH 指向 B；保存后数据库 A 不变、B 含 B 的预期图 |
| TPL-S02 | A→关闭→A，第二次读取先成功，第一次后成功/失败 | 首次会话不能覆盖第二次；不能仅按相同 ID 放行 |
| TPL-S03 | 读取中用 ×、取消、Escape、外点关闭，或切走页面 | 旧响应不重开弹窗、不写后续窗口；关闭/焦点规则保留；卸载不更新 UI |
| TPL-S04 | 新建时依次选来源 A/B/C，按不同顺序返回 | 只接受最后选择 C，来源 ID/图一致，已输入的自定义标题不被覆盖 |
| TPL-S05 | 选来源 A 后选空；A 返回；以及 A 成功→手改 M→选 B→B 失败 | 空选项不被反向改回 A；M 原文/dirty/无来源状态完整保留；过期失败不能回滚新输入；不把旧图伪装成 B |
| TPL-S06 | 编辑初始读取/来源读取中手动修改 JSON | 迟到成功/失败不覆盖输入、不给无关错误；保存的是手工内容 |
| TPL-S07 | 当前图读取失败、精确 ID 不在分页中、缺 graph | 明确失败，无自动写；编辑仅改标题时 PATCH 不含 graph 且服务端原图不变；新建无图不发 POST |
| TPL-S08 | 编辑初始图读取中只改标题；新建来源读取中点保存；JSON 解析失败 | 编辑可 PATCH 元数据但请求无 graph、数据库原图不变；新建 pending 不发 POST；无效 JSON 不发请求；草稿保留 |

| TPL-S11 | 编辑只改元数据；手改图与元数据一起提交；清空 JSON | 首项不发 graph 且旧图不变；第二项一个 PATCH 同时保存；空白编辑保留原图，空白新建拒绝 |

| TPL-S13 | 1280×720、720×900 两个明确视口，读/存/错误/等待状态 | 保留原 m77 的容器≤960及焦点返回断言；新增页面 scrollWidth≤clientWidth、弹窗不横向溢出、字段与保存/关闭按钮滚动后可见可达；迟到读取不跳焦点，A 保存与 B 等待文案正确 |
| TPL-S14 | A 保存中尝试重新编辑 A或在新建 B 中选 A 为来源；保存前列表响应迟到 | 在途不发 A 的读取；B 可正常读取；成功记录先更新再解锁，旧列表不能覆盖；解锁后新 GET 读到 A 新图/新元数据 |
