# INC-GEN-004：整组节点结束后先存稳再往下跑

状态：`PRODUCTION_PUBLISHED_AUTO_PASS / USER_RECHECK`
版本：`v0.6.12`
日期：`2026-08-18`

## 用户确认的问题

点「一键上新+自检」这类大组时，前面几个节点能跑完，后面突然弹出红字，一闪就没了。根因是整组只在开始时等画布存完；后面每个节点把结果写回画布后版本号会加一，下一个节点还拿着旧号去提交，服务器正确拒绝（409，画布还在保存）。不是画布坏了，也不是模板坏了。

## 冻结合同

- 服务器继续拒绝过期版本号和未保存内容。不放宽 409。
- 多标签仍是最后保存者胜；同一标签迟到的旧保存仍拒绝。
- 整组仍按依赖流水，无关分支自己往下走，不改回整层等齐。
- 同一层真正出图/出字/出视频仍并行；排队仍只限「等保存 → 提交任务 → 写回任务号」。
- 整组里若只是「画布还在保存」，最多再试 1 次，沿用原来的幂等钥匙。其它失败不重试。
- 错误提示留约 8 秒；进度和成功提示仍 2.6 秒。
- 不改模板、连线、模型默认值、下载、文字全屏、核对结果、重试绑定。

## 本发布范围

- 每个组内节点跑完后，等画面落稳、强制保存、等到服务器版本号对上，再让下游开工。
- 等版本号时，等一帧后再确认画布没有又变脏。
- 文字全屏（INC-UI-008）用户已在本轮明确回复通过，只改文档状态，不改该功能代码。
- 包版本升到 `0.6.12`，运行时承认该版本为 final。
