## 现状与卡点（2026-08-19 只读核对的事实）

1. 尺寸表现在写死在 `server/generationTasks.ts`，管理员后台改不了。
2. 后台「未来模型参数 → 新增参数」生成的 `custom_*` 参数带 `providerStatus: "pending"`（待平台适配），**只显示、不发到收费口**。这是故意的安全设计，不是坏了，本次也不把它改成"任意参数直发"。
3. 发送时 `size` 字段本来就在适配器白名单里（只允许 `auto` 或 `\d{2,5}x\d{2,5}`）。也就是说：**不需要开"任意参数直发"通道，只要把 size 的取值来源从写死代码改成「管理员配置 + 内置表回退」，就自然能真发。**
4. 模型参数 schema 存在 `model_profiles.default_parameters`；任务创建时会把 `parameterSchema` 快照进任务，配置一变，旧页面提交会被「平台连接或模型配置已变化」拦住（现有幂等机制）。这正好保证：改表只影响之后的新任务，旧格子重试不漂移。
5. `cleanParameterSchema` 会丢弃 schema 里的未知顶层键（构造全新对象返回）。所以新字段必须显式接入类型、清洗和校验，否则保存即丢。
6. 后台模型编辑页整体读写 `parameterSchema`（`client/src/App.tsx`），保存走现有管理员模型更新接口和审计。

## 设计

### 1. 存哪里：放进参数 schema，不加数据库表（推荐）

`ModelParameterSchema` 增加一个**可选顶层字段**：

```ts
sizeMap?: {
  "1k"?: Record<string, string>; // 比例 -> 像素，如 { "9:16": "1088x1920" }
  "2k"?: Record<string, string>;
  "4k"?: Record<string, string>;
};
```

为什么选它：

- 不需要数据库迁移、不需要 schema 版本升级（`version` 仍为 2，字段可选，旧数据不受影响）。
- 任务快照、幂等签名、备份/恢复**自动覆盖**这个字段，不用另接管线。
- 管理员编辑界面本来就整体读写这个 schema，改动最小。

备选（本轮不推荐）：`model_profiles` 加独立列 `size_map`。需要 schema40 迁移、任务快照手工携带、备份恢复和发布流程都要加，成本高且收益只是"看起来更独立"。

### 2. 校验：服务端唯一权威，防呆、防扣错钱

保存时（`server/modelCatalog.ts` 的模型更新路径）统一校验，任何一行非法就**整体拒绝保存**，不部分生效：

- 档位键只允许 `1k / 2k / 4k`。
- 比例键只允许 `auto` 或 `^\d+:\d+$`；同一档内比例键不得重复；每档最多 24 行。
- 像素值只允许 `auto` 或 `^\d{2,5}x\d{2,5}$`，且按优创官方规则：
  - 宽高都必须是 16 的倍数；
  - 单边不超过 3840；
  - 总像素在 655360 ~ 8294400 之间；
  - 长短边比例在 1:3 ~ 3:1 之间。
- 只有 `capability = image` 且 `providerProtocol = gpt-image` 的模型允许保存 `sizeMap`；其他协议即使请求里带了也拒绝，防止串到别的平台。
- 校验函数放共享类型层（`types/modelParameters.ts`），客户端实时提示与服务端最终校验用同一套规则。

### 3. 发送层：查表顺序「管理员配置 → 内置表 → 人话拦截」

`server/generationTasks.ts` 的 `gptImageSizeForAspectRatio` 改为：

1. 先查任务快照 `modelConfiguration.parameterSchema.sizeMap`：档位 + 比例都命中 → 用管理员配置的像素。
2. 没命中 → 回退当前内置文档表（INC-GEN-008 那张）。
3. 还没有 → 抛带人话提示的 `FORMAT`，不发请求、不扣费（保持现有拦截文案风格）。

其它保持不变：

- `quality` 仍只发 `auto/high/medium/low`；1k/2k/4k 只决定 `size` 像素，`quality` 发 `auto`。
- 只改 `protocol === "gpt-image"` 分支；OpenRouter、`media-generate`、视频、文字、音频不动。
- 适配器 `cleanImageRequest` 白名单不动——size 还是普通字符串，**没有新增直发收费通道**。

### 4. 后台 UI：管理员模型编辑页新增「优创尺寸映射」

只在 `capability = image` 且协议为 `gpt-image` 的模型编辑页显示；其它模型完全不出现，避免误会。

界面长这样（说人话）：

- 三档分组：1K / 2K / 4K。
- 每行两项：「比例」（下拉，来自该模型已启用的比例选项；也允许手输）+「像素」（如 `2160x3840`，或 `auto`）。
- 行内即时校验：非法像素当场标红并提示人话（例如「宽高都必须是 16 的倍数」）。
- 按钮：「加一行」「删行」「恢复内置默认」（清空，改用文档表）。
- 旁边只读展示当前内置表作参考。
- 保存沿用现有「保存模型」流程；保存后提示「只对之后新提交的格子生效」。

实现位置：`client/src/App.tsx` 的模型编辑区（或拆一个小组件文件），复用现有 schema 状态与保存接口。

### 5. 任务快照与幂等：改表不漂移

`sizeMap` 随 `parameterSchema` 一起进任务快照（现有机制自动做到）：

- 管理员改表后，**已经在跑/失败待重试的格子仍用旧配置**，不会突然变像素。
- 旧页面（旧 schema）提交新单会被「平台连接或模型配置已变化」拦住，提示刷新后重试——防止拿着旧配置发新单。

### 6. 权限与审计

- 只有管理员能进模型编辑（现有权限不变）。
- 保存 `sizeMap` 走现有 `model.update` 审计事件，明细 JSON 记录改前/改后，可追溯。

## 风险与预案

| 风险 | 预案 |
|---|---|
| 管理员填错像素 | 保存前强校验 + 只影响该模型新任务 + 审计可查 + 一键清空回内置表 |
| 填了文档没有的组合 | 发送层仍按未知组合拦截，不乱发、不扣费 |
| 渠道降采样、不保证像素 | 文档已写明；验收以落盘实际宽高为准，不谎称一定命中 |
| 旧格子重试配置漂移 | 任务快照隔离，旧任务用旧配置（现有机制） |
| 恶意/超限数值 | 服务端统一校验（16 倍数、单边 ≤3840、总像素上限、比例 1:3~3:1）整体拒绝 |
| 改坏其它平台 | 仅 gpt-image 协议放行；OpenRouter / 视频 / 通用媒体回归必须绿 |

## 明确不做

- 不做「任意参数直发收费口」：`custom_*` 参数继续保持只显示、不发。
- 不做多平台通用尺寸表：本轮只接优创 `gpt-image`（架构上留好校验函数，后续平台可按同样方式接入）。
- 不改 OpenRouter、`media-generate`、视频/文字/音频发送、DATA-005。
- 不改 INC-GEN-008 已完成的发送逻辑语义（只在查表时多一层管理员优先）。
