# INC-GEN-012：整组执行不再受画布视野影响

更新日期：2026-08-21
状态：`V0.6.26_RELEASE_CANDIDATE_AUTO_PASS / USER_RECHECK`（未发布）
目标：用户正常点击整组开始后，平移、缩放、调整窗口或把模板拖到屏幕外，都不能让后续节点静默失败；运行状态始终可见；刷新后可以在不重复付费的前提下继续剩余节点。

## 1. 已确认事实

1. `CanvasSurface.tsx` 开启 React Flow `onlyRenderVisibleElements`。离开视口的节点组件会卸载。
2. Text/Image/Video/Audio 的整组执行能力由节点组件在 `useEffect` 中注册，卸载时注销。
3. `WorkflowExecutionProvider` 根据完整画布图计算组内可执行节点，却从“当前已挂载节点注册表”执行静态预检和实际运行。因此存在两条确定性失败路径：
   - 开始时部分组内节点已离屏：静态预检报“节点尚未就绪”，零任务提交；
   - 开始后节点离屏：尚未调度的后续节点找不到 registration，失败并阻塞后代。
4. 用户已在真实页面确认：开始执行后把模板工作流拖到屏幕外，后续节点会失败，而且没有足够明确、持续可见的提示。
5. 现有 m79 只验证可视区域渲染性能；m22 只验证 DAG/整组语义。两者分别通过，不能证明“虚拟化 + 整组执行”组合正确。
6. 当前活动项目画布最大 171 节点；事故画布 98 节点。关闭全画布虚拟化会集中挂载媒体、任务恢复、metadata、音频波形等副作用，不能作为正式修复。

## 2. 产品边界

本问题不是“模板完全看不见时还要能点击开始”。准确边界是：

- 用户能看到组工具栏并正常点击开始；
- 组内可以有部分节点一开始就在视野外；
- 开始后允许用户平移、缩放、调整窗口和拖动组位置；
- 这些纯视图/位置行为不影响已经启动的 DAG；
- 运行中的配置和结构不能被同时改成另一套输入；
- 关闭浏览器后不承诺服务器自动把整条 DAG 跑完；已提交的单节点任务仍按现有服务端机制继续。

## 3. 选定实现

### 3.1 目标组执行租约

整组开始前，由 `WorkflowExecutionProvider` 对本轮可执行节点取得一次有 scope 的执行租约：

`accountId + canvasId + fixtureScopeId + groupId + runId`

租约要求：

- 只保活本次组、组内可执行节点及必要父组，不挂载全画布；
- 直接连入组内节点的组外 source 也纳入只读锁与定向保活；
- 在静态预检前取得，并等待本轮全部 registration 就绪；
- 从预检、DAG 运行、每节点保存屏障一直持有到最终摘要完成；
- 停止后续、失败和异常路径都在同一个 `finally` 中恰好释放一次；
- 新画布/新账号不能复用旧租约；旧 runId 不能覆盖新一轮。

跨标签互斥使用浏览器 Web Locks，并把锁持有到整轮 `finally`；localStorage 只保存可核对的 owner/runId/heartbeat，不承担原子互斥。没有 Web Locks 的浏览器会在付费提交前明确阻止整组执行，不使用不可靠的降级锁。

当前 `@xyflow/react` 没有“强制保留指定 nodeId”公开接口。本轮采用仅传给 React Flow 渲染层的瞬时 `dragging` 保活标记；这是明确的库适配手段，但绝不写入 `nodes` 状态、画布 document 或保存指纹。自动测试固定原节点不发生位置、选择或持久拖动状态变化。若库升级后该入口失效，组合回归必须先失败，不能静默退化。

### 3.2 固定运行快照

点击开始并通过画布保存门后，冻结本轮：

- account/canvas/group/run identity；
- 直接组成员、可执行节点、边和依赖关系；
- 每个节点开始时的模型、Prompt、参数和输入所有权摘要；
- 本轮节点状态与成功结果证明。

成功证明由节点终态持久保存 taskId、输入 ownership 与结果指纹；它不依赖生成结束后会被清空的临时 polling 字段。检查点仍独立存于浏览器 scope 存储，不写进画布图结构。

运行中允许平移、缩放和拖动位置；禁止删除组/参与节点、修改参与节点的 Prompt/模型/参数、增删参与边。避免同一轮前半段使用旧输入、后半段使用新输入。

### 3.3 独立运行状态

运行状态由 Provider 管理，不依赖 GroupNode 是否在屏幕内。状态至少包含：

- `preparing / running / stopping / success / failed / cancelled`；
- 已完成/总数、正在处理节点数；
- 成功、失败、未运行数量；
- 首个真实失败节点、错误码、原因；
- `runId/runSequence` 与 scope。

左侧“生成任务”持续展示最近一轮整组状态；最终摘要可关闭，但不能只靠 8 秒 toast。组离屏时仍可看到进度和失败原因。

### 3.4 页面离开与刷新

- 运行中刷新/关闭浏览器：使用 `beforeunload` 明确提示；
- 运行中切换项目/账号：阻止无提示离开，用户确认后只停止尚未提交的后续节点；
- 删除运行中的组或参与节点：默认阻止，不静默删除；
- 已经提交的任务继续由现有服务端任务系统处理和保存，不能宣传为已取消；
- 页面重新打开后读取持久运行检查点，显示“上次整组未完成”。

### 3.5 手动继续剩余节点

检查点只保存恢复所需最小信息，不把运行状态塞进画布 document：

- scope、groupId、runId、开始时间；
- 快照指纹；
- 已成功节点及其持久任务/输入所有权证明；
- 未完成/失败/阻塞节点；
- 最后更新时间和终态。

重新打开页面后不自动付费提交。只有用户点击“继续剩余节点”才恢复：

1. 重新读取画布完整图；
2. 核对 scope、组和快照；
3. 对每个成功节点核对当前持久 ownership/task 证明；
4. 证明不一致的节点不能当作成功复用；
5. 服务端已有任务先 exact reconcile；
6. 只调度仍未完成且允许继续的节点；
7. 同一输入绝不因为恢复而创建第二个付费任务。

无法证明安全复用时必须停下并说清楚，不自动猜测重跑。

## 4. 并发与编辑规则

- 同一组同一时间只允许一轮；双击合并。
- 第一版同一画布只允许一个整组运行，避免两个组共享节点或同时写画布产生结果覆盖。
- 单节点生成正在参与同一组时，整组开始被阻止。
- 运行中的组仍可移动位置；参与节点内容与结构只读。
- 点击“停止后续”后不再调度新节点；已开始节点继续完成并保存。
- 刷新恢复与当前页面运行使用同一 scope/run fence，旧页面迟到结果不能覆盖新一轮摘要。

## 5. 不采用的方案

- 不关闭全画布虚拟化：会挂载 98～171 个节点并放大媒体加载、轮询、波形和保存副作用。
- 不只删除 registration cleanup：会保留旧闭包、旧 Prompt、旧画布和旧任务上下文。
- 不靠 fit view/自动缩放把所有节点塞进屏幕：用户再次移动就会复发。
- 不伪装“停止后续”为批量取消 Provider：已提交任务的取消与付费结果并不一致。
- 不在本轮建设浏览器关闭后服务端自动编排完整 DAG、跨设备接管或通用工作流平台。

## 6. 必须覆盖的验收矩阵

### 6.1 视野组合

- 组内全部可见；
- 开始前部分子节点离屏；
- 运行中平移、缩放、窗口 resize；
- 当前节点离屏；
- 尚未调度的下游离屏；
- 整组拖到屏幕外后继续完成；
- 再拖回屏幕内，状态和位置不异常。

### 6.2 DAG 与失败

- 分流独立推进、汇流严格 AND；
- 一个分支失败只阻塞后代；
- 失败摘要指向真实失败目标节点；
- 停止后续不再提交新节点；
- 已开始节点仍完成并保存。

### 6.3 编辑、离开与恢复

- 运行中结构/配置编辑受控；
- 删除组/节点受控；
- 切项目、刷新、关闭均有明确提示；
- 重新打开能识别未完成运行；
- “继续剩余节点”复用已成功节点；
- 快照不一致时 fail-closed；
- 旧轮次不能覆盖新轮次。

### 6.4 防重复与性能

- 双击开始只产生一轮；
- 恢复/继续不重复生成成功节点；
- 网络丢响应仍先 exact reconcile；
- Provider POST 和 generation task 数量与预期节点一一对应；
- 98/171/200 节点画布不全量挂载；
- 平移性能不明显退化；
- 租约释放后离屏节点恢复正常卸载；
- 4173、`app/data`、真实媒体、真实 Provider/OSS 均不被测试触碰。

## 7. 实施顺序

1. 新增运行 scope、快照、检查点和状态类型；
2. 接入目标组执行租约，先补“离屏预检/运行失败”的红测；
3. 增加运行中编辑/删除/离开保护；
4. 左侧任务面板增加持续运行状态与继续入口；
5. 增加刷新后识别与手动继续剩余节点；
6. 运行 m22/m38/m79、相关画布/任务面板专项、build；
7. 通过唯一安全入口运行正式 full；
8. 独立 review 后同步 CURRENT_STATE、TASKS、验收矩阵和本文实际证据。

## 9. 2026-08-21 实施与验证证据

已落地：

- 点击开始即锁定本组、子节点和直接外部输入源；整组父框仍可拖动，组内参与节点与结构只读；
- 仅用 React Flow 渲染克隆保活离屏参与节点，真实 `nodes`、位置、选择和保存指纹不写入瞬时 `dragging`；
- preparing/running/stopping 持续摘要、任务面板停止入口、离开/刷新提示、异常终态与手动继续入口；
- 成功 proof、结果指纹核对、快照变化 fail-closed、在途节点等待现有恢复结果、不自动二次提交；
- Web Lock 全程互斥、owner/runId 检查、heartbeat、旧 lease 事件停止；
- 双击开始合并；快速第二击不会在按钮刚切为“停止”时误停；
- 运行中阻断删除、解组、缩放、配置、连线、复制粘贴和 undo/redo，保留父组移动、画布平移缩放及已提交任务自然完成。
