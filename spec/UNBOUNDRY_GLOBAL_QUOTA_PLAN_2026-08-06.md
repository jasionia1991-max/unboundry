# 全局额度管理（方案A）实现记录

状态：`APPROVED`（用户 2026-08-06 确认参数：全局单次默认 ¥20、汇率 7.2 可改）

## 1. 目标

把“每个模型单独填单次费用 + 美元/人民币两套上限”的繁琐管理，收敛为：

- 一个全局预算（人民币）：每日、每月各一个数字；
- 一个单次任务默认上限（人民币，默认 ¥20）；
- 一个汇率（1 美元 = 7.2 人民币，可改）；
- 模型自己的单次费用变成“可选覆盖”，留空/0 使用全局默认；
- 模型不再因为“没填单次费用”而不可生成。

## 2. 语义与实现

### 2.1 底层记账不变

- 任务成本仍按原币种（CNY/USD）记录在 `generation_tasks`，历史成本不重算；
- 费用判定仍按币种执行；
- 新增“合并折算检查”：当天/当月 `CNY 实际 + USD 实际 × 汇率` 也不能超过人民币预算，
  实现真正共享的全局额度。

### 2.2 美元线自动派生

- 美元每日/每月上限 = 人民币预算 ÷ 汇率（四舍五入到微元）；
- 修改汇率后立即生效（上限动态换算），不重写历史成本；
- 老接口/老页面 PUT 设置时，缺省的新字段回退为当前库内值，不会静默重置。

### 2.3 单次费用

- `single_task_default_cost_cny_microunits`（默认 20_000_000 = ¥20）；
- 模型 `max_cost_microunits > 0` 时用模型值（保留币种），否则按模型币种取全局默认
  （USD 默认 = ¥20 ÷ 汇率）；
- 该“有效单次成本”同时驱动：估算成本、费用准入、任务创建、以及
  `paidArkVideo/paidArkText/paidMurekaAudio` 安全标志（防止 0 上限模型跳过
  Base64 体积、视频/音频时长、参考素材等校验）。

### 2.4 模型可用性

- 移除 `COST_LIMIT_NOT_CONFIGURED`：`max_cost = 0` 不再导致模型不可生成；
- 管理端模型列表返回 `effectiveMaxCostMicrounits`，界面显示“留空使用全局默认”。

## 3. 改动范围

- `database.ts`：迁移 v27，新增两列并带默认值；
- `generationSafety.ts`：类型/保存/准入（派生美元线 + 合并检查）、
  `effectiveSingleTaskCostMicrounits` 共享助手；
- `modelAvailability.ts`：移除费用未配置阻断；
- `generationTasks.ts`：提交链全部改用有效单次成本；
- `modelCatalog.ts`：管理端模型返回有效单次成本；
- `App.tsx`：生成安全中心改为全局预算界面；模型中心单次费用可选；
- `openApi.ts` / 前端类型：移除 `COST_LIMIT_NOT_CONFIGURED`；
- 测试：m14（新增美元线派生、合并检查、旧接口兼容）、m32（0 上限模型可生成）。

## 4. 预审计风险与应对（已在实施中落实）

| 风险 | 应对 |
|---|---|
| 合并折算让美元/人民币共享额度、可能更早触顶 | 明确这是“全局”语义；保留分币种线 + 合并线双检查 |
| 0 上限模型被当成“不花钱”跳过安全校验 | 所有 paid 标志改用有效单次成本，专项测试覆盖 |
| 全局默认误设 0 导致全部 COST_UNKNOWN | 校验强制 ≥ 0.01 元 |
| 汇率取整误差 | 全部 round 到微元，误差 < 1 分 |
| 旧接口 PUT 不带新字段导致重置 | update 以当前值兜底 |
| 美元线从 20 美元突变为 0.69 美元 | 美元线按汇率动态派生、迁移后立即生效；管理员在界面调整人民币预算即可放宽 |
| `COST_LIMIT_NOT_CONFIGURED` 移除后旧模型突然可用 | 这是目的；界面提示“留空使用全局默认” |
| 整组执行费用文案联动 | 保持 `COST_LIMIT` 与“今日费用额度已用完”文案不变 |

## 6. 验收

1. 生成安全中心只显示：每日/每月全局预算（¥）、单次任务默认上限（¥）、汇率；
2. 模型中心单次费用留空 = 全局默认；
3. 美元任务与人民币任务共享预算（合并线）；
4. 管理员保存后，美元线按汇率换算展示。
