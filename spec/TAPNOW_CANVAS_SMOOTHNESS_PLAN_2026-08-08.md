## 1. 问题与证据（2026-08-07/08 真实 Chrome 实测）

### 1.1 帧指标（同机同手势，CDP 附着用户调试窗口）

| 场景 | FPS | 丢帧(>24ms) | 最大帧 | 主线程长任务 |
|---|---|---|---|---|
| 我们 28 节点·缩放 | 126 | 3 | 83.3ms | 3 次（91/55/56ms） |
| 我们 28 节点·拖节点 | 134 | 1 | 27.9ms | 0 |
| 我们 60 节点·拖节点 | 94 | 6 | 41.8ms | 0 |
| TapNow 12 可见节点·缩放 | 116 | 1 | 27.8ms | 0 |
| TapNow 12 可见节点·拖节点 | 144 | 0 | 13.9ms | 0 |

### 1.2 归因（长任务栈 + JS 采样）

- 我们 93ms 长任务栈 = react-dom 渲染循环（`performWorkUntilDeadline`）；JS 采样大头 = JSX 元素创建（约 18%，dev 模式）、React 提交、指纹递归序列化（`canonical`）、GC。
- 根因 1：`viewport` 受控在 `CanvasShell`（CanvasShell.tsx:702），缩放/平移每帧触发整壳 + CanvasSurface 重渲染。
- 根因 2：8 种节点组件均无 React.memo；60 节点时拖拽 94fps、6 次丢帧。
- 根因 3：持久化 watcher 每帧执行整文档克隆 + 双指纹（`canvasSnapshot()` → `canvasDocumentFingerprint/canvasGraphFingerprint`）；虽有 500ms 防抖保证拖拽中不写库，但指纹计算每帧都在做。
- 根因 4：节点全量常驻 DOM（66/66）；TapNow 实测按视口挂载/卸载节点（28→2→0），且拖拽路径几乎不进 React（JS 时间 81% 空闲）。
- TapNow 侧同样有 JS 总量（缩放 3.1s，含 Clarity 埋点），但无 ≥50ms 长任务，帧不被阻塞。

## 2. 修复步骤

### STEP 1：交互热路径解耦（不动契约）

范围：
1. viewport 从 CanvasShell 下沉到 CanvasSurface 内部（ref 为实时真相，ReactFlow 改非受控 viewport）；外壳只保留低频 `zoom` 摘要（约 4–6 次/秒 + 停手必更新）驱动缩放滑块/指示条；滑块输入改命令式 `zoomRequest`。
2. 持久化 watcher 增加“交互安静期”：拖动/缩放/平移期间跳过指纹计算与保存调度，停手安静 ≥250ms 后重新评估并照常 500ms 防抖保存；保存语义、多标签 last-writer-wins、revision/sequence、pagehide keepalive、生成前 flush 全部不变。
3. 新增“停手后必然触发保存”断言（真实画布拖节点后等待，断言 PUT 发生且发生在停手后）。

验收：tsc/构建；m1-dense、m3、m27、m62、m68、m69、m70、m71、m0 相关回归全绿；真实 Chrome 28 节点缩放长任务从 3 次 → 0、最大帧 <30ms；用户实页确认。

回退：单独提交可回退；不 push。

STEP 1+1b 实测（真实 Chrome，28 节点临时项目，两轮稳定）：缩放 120/121fps、0 长任务、p95 9ms、max 9ms（达标）；平移 120fps、0 长任务、max 9ms（达标）；拖动 104–106fps、2 次长任务（81/85ms，p95 9ms）。拖动残留归因：节点组件无 memo，位置更新全量重渲染 → STEP 2。

STEP 1b 关键实现：ReactFlow 去掉受控 viewport prop（真正非受控）；viewportRef 为实时真相，data-viewport-* 由 DOM 直写；仅多选状态才同步 React viewport 状态（工具栏定位）；程序化视口变化显式触发交互安静期保证保存；动画期间 tick 不触发保存重查。

STEP 2a（memo）：8 种节点组件与 CuttableEdge 包 React.memo；拖动中的每次位置变化重置交互安静期（防长拖中途保存）。

STEP 2 实测：开发模式拖动仍有 dev 模式 React 元素检查开销（28 节点 3 长任务/60 节点 72fps）；生产构建拖动 28/60 节点 119-120fps、0 长任务（达标），200 节点 66fps（需可视区域渲染）。结论：日常 60 节点级画布在 `vite preview`（生产构建）下已达标；200 节点压力仍需 STEP 2b 可视区域渲染。

STEP 2b（可视区域渲染）：启用 ReactFlow `onlyRenderVisibleElements`；200 节点生产构建拖动 119fps/0 掉帧/p95 9ms；快速平移节点实时挂载无空白；缩小视图全量挂载。契约测试同步（DOM 计数 → data-* 属性）。

STEP 3（门禁）：m1-dense 收紧为长任务 <100ms、p95 ≤25ms、最大帧 <100ms；新增生产构建专项 `m79-canvas-smoothness`（60 节点拖动丝滑、快速平移实时挂载、缩小全量挂载）。

收尾动作：4173 launchd 由 `vite dev` 切换为 `vite preview`（生产构建）并重启；切换后代码变更需 rebuild+restart。

### STEP 2：渲染架构（可视区域 + 缓冲带 + 缓存）

范围：
1. 节点组件 React.memo + 稳定 data 引用（未变节点不重渲染）。
2. 只渲染“屏幕 + 缓冲带（约一屏）”的节点；离开缓冲带的节点卸载但进入 DOM/素材缓存（LRU，短期保留）；拖回秒现。
3. 素材只算一次：音频波形、视频封面、缩略图等复用缓存。
4. 交互中的节点（选中/编辑/播放/弹层）强制保留不卸载；父节点可见则子节点可见；连线只在缓冲带内绘制；小地图用全量数据独立绘制。
5. 200 节点压力测试：不劣化、无空白等待。

风险与应对：快速远拖空白 → 缓冲带 + 缓存 + 专用“快速远拖素材实时出现”验收；组/边/小地图异常 → 对应规则与回归；正在交互节点卸载 → 强制保留；旧决策 → 已由用户确认推翻。

验收：真实 Chrome 60/200 节点拖拽回到 110fps 档、无长任务、快速远拖素材实时出现；用户实页确认。
